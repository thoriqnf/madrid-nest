## 🛡️ Feature Details

### 1. Password Hashing (The "Highlight")
We use `bcrypt` with **10 salt rounds**.
* **Why?**: Increasing rounds makes the hash slower, protecting against brute-force even if the database is leaked.
* **Salt**: Automatically generated by `bcrypt.hash()`, preventing rainbow table attacks.

### 2. Input Validation
Every request body is validated against a DTO.
```typescript
@IsEmail()
email: string;

@IsStrongPassword() // Ensures length, uppercase, numbers, and symbols
password: string;
```

### 3. Rate Limiting
Public endpoints like `/auth/login` are capped to 5 requests per minute per IP to prevent automated guessing.

### 4. Refresh Tokens
Instead of long-lived access tokens, we use:
1. **Access Token**: Short-lived (15m).
2. **Refresh Token**: Long-lived (7d), used only to get a new Access Token.
